Day one is where setup docs fail.

Nobody breaks a README on purpose. A version moves on, a service gets added, a step lives in someone's head. The docs still read fine; they just stopped being true.

The person who finds out is the newest one on the team, on their first morning, with nobody to ask.

How it works

IBM Bob runs HUMBLE. He reads the repo, sends in a crew of six agents, and steps in when the rules can't explain a failure.

  1. 01

    Scout

    Reads the docs next to what is actually true: manifests, lockfiles, compose files, CI and code.

  2. 02

    Planner

    Turns the prose into the exact commands a newcomer would run, in order, and flags where docs and code disagree.

  3. 03

    Runner

    Runs every step on a brand-new machine. Nothing installed, nothing assumed.

  4. 04

    Doctor

    When a step breaks, finds out why. Known causes get known fixes; the rest go to IBM Bob.

  5. 05

    Verifier

    Throws the machine away and replays the repaired guide from zero. A fix only counts if it passes here.

  6. 06

    Scribe

    Writes the smallest README change that makes it true, with the evidence for every line.

    Doctor. When no rule recognises a failure, Bob reads the repository and returns a structured fix. HUMBLE refuses anything that would change the application itself and keeps it as a suggestion for the maintainer.

    Guide mode. A newcomer switches Bob to Guide mode and gets walked through the verified steps on their own machine, one at a time.

    Lens. Circle an error anywhere on screen. If HUMBLE has already proven a fix for it, you get that fix instantly; otherwise Bob explains it.

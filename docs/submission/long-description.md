Setup documentation drift is the silent tax on every new contributor. A repository's README describes the setup as it was written, not as it is. Versions move on, services are added, and steps live in tribal knowledge. The person who discovers the gap is the newest team member on their first morning, with nobody to ask. Research from Atlassian DevEx 2025 and Cortex 2024 shows onboarding friction as the top developer-experience pain point and new hires taking over a month to land their third pull request.

HUMBLE treats a repository's setup docs as an executable procedure. It follows the documented steps on a clean Linux machine (a Docker container with no cache, no pre-installed tools, no host leakage) exactly as a newcomer would. The pipeline runs six specialized agents in sequence: Harvey reads the docs next to manifests, lockfiles, compose files, CI workflows, and application code to build a fact base. Unity turns prose into the exact ordered shell commands a newcomer would run, flagging where docs and code disagree. Mach executes every step on the clean machine with per-step timeouts (5 minutes for test, 25 minutes for install, 12 minutes for build, 150 seconds for serve). DR.BO diagnoses failures - known causes get known fixes from a deterministic rule set; when no rule recognizes the failure, DR.BO calls IBM Bob to read the repository and return a structured fix that changes only documentation, environment templates, compose files, or runtime version files - never application source. Larp discards the machine and replays the repaired guide from zero on a fresh container, proving every fix works end to end. Echo writes the minimal README diff, patches .env.example or docker-compose.yml, and emits a Setup Passport with evidence for every change (failure log, root cause, fix applied, replay pass).

IBM Bob 2.0 is the core diagnosis and onboarding component in HUMBLE. The engine uses Bob in three integrated ways: deterministic Doctor rules run first for common failure classes (missing services, version mismatches, placeholder env values, peer-dependency conflicts, port collisions, missing global tools). When no rule recognizes a failure, the Doctor invokes Bob Shell in the DR.BO custom mode headlessly. Bob reads the repository (docs, manifests, config, the code that raised the error) and returns a single JSON object matching the HUMBLE fix schema: a root-cause string, an optional action list (rebase image, write file, add service), optional doc patches, and a needs-human flag. HUMBLE validates the response structure, refuses any action that would change application source code, and keeps code-only fixes as maintainer suggestions.

Bob IDE custom modes ship in .bob/custom_modes.yaml and install globally for Bob Shell via `firstrun bob install`. Four modes cover the pipeline: HUMBLE (orchestrator - plans, verifies, audits), Doctor (read-only diagnosis, used headlessly by the engine), Planner (read-only extraction of setup commands from prose and PDFs), and Guide (walks a newcomer through the verified steps on their own machine, one at a time, applying recorded fixes when known failures appear). The engine calls Bob Shell with these modes as subagents; Bob IDE users interact with them directly.

Bob's MCP integration exposes firstrun_plan, firstrun_verify, firstrun_status, firstrun_evidence, and firstrun_drift tools so the HUMBLE mode can drive the pipeline from inside Bob IDE without CLI calls. The custom modes declare the MCP group and restrict edits to HUMBLE output paths (.firstrun/, audit/, FIRSTRUN.md). Budget and evidence recording are built in: every headless Bob call consumes Bobcoins logged in the task session summary; the Doctor mode's structured JSON output becomes an evidence record in the Setup Passport (id, stepId, before, after, cause, fix, verified).

Lens is a companion Electron app that captures screen regions, runs OCR (Tesseract.js), matches the text against HUMBLE's known failure signatures, and surfaces the proven fix instantly; if no signature matches, it opens the error in Bob's chat for explanation. All text is processed locally; only a user-initiated question reaches Bob.
